### Браузерные тесты

```bash
./e2e.sh                      # весь набор, ~1 минута
./e2e.sh plan                 # один файл
./e2e.sh -g "перетаскивание"  # один тест
./e2e.sh --keep               # оставить стек на localhost:8080
```

Playwright + Chromium в официальном образе, поэтому в WSL ставить нечего.
Стек свой (`docker-compose.e2e.yml`, имя проекта `lesson-tracker-e2e`):
nginx с **собранным** бандлом, gunicorn, база в tmpfs. Против dev-сервера
гонять бессмысленно — вёрстка и `ReferenceError` ломаются именно в сборке.

Два отличия от прода, оба вынужденные: `DEBUG=True` (иначе `seed_demo`
откажется работать, а его защита дороже совпадения флага) и
`E2E_TEST_LOGIN=true`. Ключей R2 у стенда нет намеренно: тесты не должны
писать в чужой бакет, поэтому в этих прогонах у уроков есть содержание и
ссылки, но нет файлов — жизненный цикл файла проверяют питоновские тесты.

`backend` объявлен с healthcheck, и nginx ждёт именно его, а не просто
старта контейнера. Команда backend'а выполняет `migrate`, `seed_demo` и
`collectstatic` **до** gunicorn, поэтому «gunicorn отвечает» и значит
«стенд готов». Без этого первый тест иногда получал 502, а при `retries: 0`
это падение всего прогона на пустом месте.

**Вход.** Через Google headless-браузер не проведёшь, поэтому в
`accounts/e2e.py` есть дверь: `POST /api/test/login/` отдаёт токен по email,
`GET /api/test/people/` перечисляет, кто есть в базе, `POST /api/test/reset/`
перезаполняет её. Она закрыта трижды: при выключенном флаге маршруты **не
регистрируются вовсе** (обычный 404), вьюха проверяет флаг ещё раз, а сброс
зовёт `seed_demo`, который не работает при `DEBUG=False`. `E2EDoorTests`
следит, что по умолчанию дверь закрыта, а тест-раннер (`config/testing.py`)
принудительно её закрывает: на стенде разработки флаг включён, и сторож,
читающий окружение, проверял бы `.env` запустившего, а не код.

**Той же дверью пользуется разработчик.** В `.env` стоит
`E2E_TEST_LOGIN=true`, и в меню пользователя появляется «Войти как» —
список посеянных людей, клик меняет токен и перезагружает страницу. Иначе
на класс из тринадцати учеников нужно тринадцать гугл-аккаунтов, а
плюс-адреса тут не работают вовсе: под алиасом в Google не войти, id_token
всё равно придёт с канонического адреса. Пункт меню появляется, только если
дверь ответила: в проде маршрута нет, и проверять переменную сборки не
требуется. Настоящий вход через Google так не проверить — для этого нужен
второй настоящий аккаунт, и для него есть домен школы.

**Главное в этих тестах — не утверждения, а слушатель консоли.** Любая
ошибка в консоли или необработанное исключение роняют тест, чем бы он ни
занимался: дважды страница уезжала в прод с `ReferenceError`, который
`vite build` не видит, потому что код не выполняет. Список исключений в
`e2e/tests/harness.js` короткий и каждый пункт с причиной — иначе сторож
тихо перестаёт быть сторожем. Проверено поломкой: подставленная переменная
в `TermsPanel` валит обход разделов с текстом `ReferenceError`.

Состояние чистое перед каждым тестом: фикстура `seeded` дёргает сброс. В
разметке есть якоря для тестов — `data-date` в сетке календаря,
`data-day-head`/`data-add`/`data-lesson` в недельной сетке; по тексту числа
в нужный месяц не попасть.

**Два прогона разом невозможны**, и это не ограничение, а следствие: имя
проекта у стенда фиксированное (`lesson-tracker-e2e`), поэтому второй
`./e2e.sh` пересоздаёт те же контейнеры — то есть сносит стек из-под
первого. Фоновый прогон при этом умирает на середине с `SIGTERM`, и в логе
это выглядит как непонятный обрыв. Пока идёт полный набор, точечные запуски
ждут.

`package-lock.json` обновляется без установки пакетов на хост:

```bash
cd frontend && docker run --rm -v "$PWD:/app" -w /app --user "$(id -u):$(id -g)" \
  node:22-alpine npm install --package-lock-only
```
