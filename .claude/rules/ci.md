## Проверка на GitHub — те же три уровня

`.github/workflows/tests.yml` гоняет **тот же docker compose**, а не
собранную рядом «нативную» установку: второй способ запустить те же тесты
однажды разошёлся бы с первым, и узнали бы мы об этом по зелёному CI при
красном ноутбуке.

| событие | что идёт |
|---|---|
| пуш и PR | питон, узловые, `./e2e.sh --smoke` |
| ночью (cron) и по кнопке | полный браузерный, четырьмя шардами |

Шарды разложены `--shard=N/4`, и e2e.sh для этого править не пришлось: всё,
чего он не разобрал сам, уезжает в playwright насквозь. Одинаковое имя
compose-проекта им не мешает — шарды идут на разных раннерах; на одной
машине два прогона по-прежнему невозможны.

**Одна правка в e2e.sh для этого понадобилась**: `docker compose run` без
терминала спотыкается о «the input device is not a TTY», поэтому `-T`
подставляется, когда терминала нет. Локально флаг не ставится — с ним
пропадает цвет и посекундный вывод, а смотрят на него глазами.

Раннер начинает с чистого клона без единого ключа, то есть ровно с того, с
чего начинается облачная сессия. Поломку «сторож пустоты падает без ключей
R2» такой прогон нашёл бы сам, и в этом главная его ценность помимо
зелёной галочки.
