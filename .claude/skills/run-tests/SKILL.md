# Прогон наборов

**Какой набор гнать — решает дифф, и это правило живёт в `CLAUDE.md`**
(«Какие тесты гонять и когда»): оно нужно до того, как что-то запускать, и
поэтому не здесь. Здесь — как запускать и обо что спотыкаются.

Наборов два. Браузерных тестов в проекте нет с 25 сентября 2026 — ни на
машине, ни на GitHub; интерфейс смотрят глазами на dev-сервере.

## Команды

```bash
docker compose exec backend python manage.py test --keepdb   # питоновский набор
docker compose exec backend python manage.py test --keepdb plans   # одно приложение
docker compose exec frontend npm test                # узловые тесты, секунды
```

**`--keepdb` — умолчание на своей машине, и это замер.** Создание тестовой
базы со всеми миграциями стоит около 32 секунд при наборе в 254 секунды, то
есть примерно восьмую часть каждого прогона, и платится она заново каждый
раз. Приехавшая чужая миграция при этом не теряется: Django с `--keepdb`
**применяет новые миграции** к сохранённой базе. Не заметит он только
миграцию, переписанную **на месте** (правка уже применённой), — после такого
базу надо снести один раз, командой из раздела ниже.

На CI флага нет и быть не должно: раннер начинает с чистого клона, и база,
созданная с нуля, — часть того, что он проверяет.

## На GitHub

Задачи `python` и `node` идут на каждый пуш любой ветки. Прод двигается
только на коммит, у которого обе зелёные, и только по просьбе человека.

Зелёный прогон или нет — **один** `gh run watch`: он блокируется и
возвращается сам. Опрашивать `gh run list` в цикле не надо, это стоит круга
модели на каждый вызов (замер — в `docs/why-these-rules.md`). Красный
разбирается логом задачи и точечным запуском упавшего теста тут же.

## Обо что спотыкаются

- **Показывайте ход.** Питоновский набор идёт минуты, и снаружи это
  молчание: раз в ~25 секунд сообщайте, сколько тестов пройдено.
- **Прерванный питоновский прогон оставляет за собой базу.** Убили фоновый
  `manage.py test` — на сервере остаётся `test_lessons` и соединение в
  состоянии `idle in transaction`. Следующий запуск спрашивает «удалить
  существующую тестовую базу?», а запускают его обычно с `< /dev/null` (см.
  `exec -T` в `CLAUDE.md`) — вопрос уходит в пустоту, и набор падает
  `DuplicateDatabase`, не выполнив ни одного теста. Выглядит как поломка кода,
  хотя код ни при чём. Лечится одной командой, обычный `DROP` тут не проходит
  — соединение живёт дольше процесса:

  ```bash
  docker compose exec -T db psql -U lessons -d postgres \
      -c 'DROP DATABASE IF EXISTS test_lessons WITH (FORCE);' < /dev/null
  ```
- **`locales.test.js` читает `backend/config/errors.py`**: правка кодов
  ошибок требует и узловых.
- **Тесты никогда не ходят в R2**: раннер подменяет хранилище на память.
- **Тесты никогда не платят за чтение сканов**: раннер обнуляет ключи
  Anthropic, Mathpix и Yandex (`config/testing.py`).

Устройство задач на GitHub — `.claude/rules/ci.md`.
