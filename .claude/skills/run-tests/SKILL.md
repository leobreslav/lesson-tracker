# Прогон наборов

**Какой набор гнать — решает дифф, и это правило живёт в `CLAUDE.md`**
(«Какие тесты гонять и когда»): оно нужно до того, как что-то запускать, и
поэтому не здесь. Здесь — как запускать и обо что спотыкаются.

## Команды

```bash
docker compose exec backend python manage.py test    # питоновский набор
docker compose exec frontend npm test                # узловые тесты
./e2e.sh --smoke                                     # дымовой, ~80 с
./e2e.sh                                             # полный браузерный, ~8.5 мин
./e2e.sh plan                                        # один файл
./e2e.sh -g "перетаскивание"                         # один тест
./e2e.sh --keep                                      # оставить стек на localhost:8080
```

## Как гонять долгое

- **Полный браузерный — в фоне**, и пока он идёт, пишутся `CLAUDE.md` и
  сообщение коммита. Условие одно: фоновый прогон стартует, когда **все**
  правки кода и тестов закончены, иначе `--build` заберёт в бандл половину
  работы. Проза в контекст сборки не входит, её править во время прогона
  безопасно.
- **Показывайте ход.** Долгий прогон снаружи выглядит молчанием: раз в
  ~25 секунд сообщайте, сколько тестов пройдено из скольких.
- **Полный набор не гоняется дважды за задачу.** Сначала все правки, потом
  единственный полный прогон.

## Обо что спотыкаются

- **Два прогона разом невозможны.** Имя compose-проекта у стенда
  фиксированное (`lesson-tracker-e2e`), поэтому второй `./e2e.sh` пересоздаёт
  те же контейнеры и сносит стек из-под первого — фоновый прогон умирает на
  середине с `SIGTERM`, и в логе это выглядит как непонятный обрыв. Пока идёт
  полный набор, точечные запуски ждут.
- **Ретраев нет намеренно**: зелёное со второго раза — не зелёное.
- **Прерванный питоновский прогон оставляет за собой базу.** Убили фоновый
  `manage.py test` — на сервере остаётся `test_lessons` и соединение в
  состоянии `idle in transaction`. Следующий запуск спрашивает «удалить
  существующую тестовую базу?», а запускают его обычно с `< /dev/null` (см.
  `exec -T` в `CLAUDE.md`) — вопрос уходит в пустоту, и набор падает
  `DuplicateDatabase`, не выполнив ни одного теста. Выглядит как поломка кода,
  хотя код ни при чём. Лечится одной командой, обычный `DROP` тут не проходит
  — соединение живёт дольше процесса:

  ```bash
  docker compose exec -T db psql -U lessons -d postgres \
      -c 'DROP DATABASE IF EXISTS test_lessons WITH (FORCE);' < /dev/null
  ```
- **Главное в браузерных — слушатель консоли.** Любая ошибка в консоли
  роняет тест, чем бы он ни занимался. Если тест упал «не по теме» — сначала
  ищите `ReferenceError`, а не правьте утверждение.
- **Появился экран — допишите его в `PAGES`** в `e2e/tests/controls.spec.js`,
  иначе браузер туда ни разу не заглянет.
- **Тесты никогда не ходят в R2**: раннер подменяет хранилище на память.

Устройство стенда и дверь входа — `.claude/rules/e2e-tests.md`.
Те же три уровня на GitHub — `.claude/rules/ci.md`.
