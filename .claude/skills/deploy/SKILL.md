# Выкатка на прод

Устройство контура — три env-файла, nginx, отличия prod-стека — в
`.claude/rules/deploy.md`. Здесь только порядок действий и то, обо что
спотыкаются.

## Правило, которое старше техники

**Выкатка — по отдельной просьбе.** Коммит и пуш идут в конце задачи сами;
прод — только когда об этом попросили. Это не осторожность вообще: на том
конце живая школа с чужими данными.

## Порядок

```bash
./push-deploy.sh "текст коммита"     # коммит + пуш + деплой + проверка сайта
./push-deploy.sh --deploy-only       # ничего не коммитить, только раскатать
```

Скрипт сам проверит, что вы в корне репозитория, на `main` и что в рабочем
дереве нет секретов, — `git add -A` иначе утащил бы их в коммит.

Флаги: `--deploy-only`, `--no-verify` (не проверять сайт), `--skip-env` (не
трогать `.env.prod`).

## Обо что спотыкаются

- **Скрипту нужен терминал — но только когда набор переменных менялся.**
  `.env.prod` синхронизируется **до** выкатки, и при расхождении скрипт
  спрашивает `[y/N]`; без TTY `read` падает с «ввод прерван». Обход через
  `script -qec` с `printf 'y'` на вход **не работает**: проверено — процесс
  простоял одиннадцать минут на вопросе, ничего не выкатив, и выяснилось это
  только по тому, что на сервере не появилось ни резервной копии, ни новой
  переменной.

  Если переменные не менялись, скрипт не спрашивает ничего. Если менялись —
  шаг env делается руками, теми же действиями, что и скрипт: копия
  `.env.prod.bak.<дата>` с `chmod 600` (хранить три последние), `scp`,
  `chmod 600`, сверить `sha256sum` с локальным файлом. Дальше
  `./push-deploy.sh --deploy-only --skip-env` проходит без вопросов.

  Из сессии Claude Code проще попросить пользователя выполнить
  `! ./push-deploy.sh …` — так вопрос задаётся в его терминале.
- **Перед выкаткой — полный браузерный набор** (`./e2e.sh`), а не дымовой:
  это один из двух случаев, когда он обязателен. Правило и цена — в
  `CLAUDE.md`, «Какие тесты гонять и когда».
- **Правка nginx применяется не всегда.** `git pull` меняет файл заменой, а
  bind-mount держит inode: контейнер до конца жизни видит прежний конфиг.
  `deploy.sh` сверяет sha256 с содержимым контейнера и пересоздаёт его только
  при расхождении — обычная выкатка nginx не трогает. Если правка конфига «не
  доехала», смотреть надо сюда.
- **Миграции идут при старте контейнера** (`migrate --noinput`), отдельно
  запускать не нужно.
