# Переменные окружения

Один список на все контуры. Составлен по `backend/config/settings.py`, а не
по памяти: умолчания в таблице — те самые, что стоят в коде.

## Где какой файл

| файл | контур | в git | кто пишет |
|---|---|---|---|
| `.env` | разработка | нет | `scripts/dev-env.sh`, если файла нет |
| `frontend/.env` | разработка, сборка Vite | нет | он же |
| `~/secrets/lesson-tracker.env.prod` | боевой | нет | человек; на сервер везёт `scripts/sync-env.sh prod` |
| `~/secrets/lesson-tracker.env.staging` | стенд | нет | человек; на сервер везёт `scripts/sync-env.sh staging` |
| `~/secrets/lesson-tracker.env.local-prod` | прод-сборка на localhost | нет | человек |
| `.env.example`, `.env.prod.example` | форма файлов | да | человек |

Существующий `.env` скрипт не трогает **никогда**: там могут лежать
настоящие ключи, и «свежие умолчания» поверх них отбирают доступ к бакету.

## В облачной сессии — пусто

В диалоге окружения на claude.ai/code поле **Environment variables** остаётся
пустым, и это решение, а не недоделка: отдельного хранилища секретов у
площадки нет, а переменные окружения читает любой, кто пользуется этим
окружением. `.env` там создаёт `scripts/dev-env.sh` — с пустыми ключами.

Каждая пустота ниже — рабочее состояние, а не заглушка: приложение
поднимается, а недоступное честно отказывает своим кодом ошибки.

## Django и база

| переменная | что делает | умолчание | пустая значит |
|---|---|---|---|
| `DEBUG` | режим Django | **нет умолчания** | Django не стартует вовсе |
| `SECRET_KEY` | подпись сессий и токенов | `dev-insecure-key-change-me` | в бою — обязательна, генерируется один раз |
| `ALLOWED_HOSTS` | список через запятую | `localhost,127.0.0.1` | чужой Host получает 400 |
| `POSTGRES_DB` | имя базы | `lessons` | |
| `POSTGRES_USER` | пользователь | `lessons` | |
| `POSTGRES_PASSWORD` | пароль | `lessons` | в бою — свой |
| `POSTGRES_HOST` | хост | `db` (имя сервиса compose) | |
| `POSTGRES_PORT` | порт | `5432` | |

`DEBUG` — единственная переменная без умолчания, и это намеренно: молча
подняться в боевом режиме с отладкой приложение не должно.

## Вход через Google

| переменная | что делает | пустая значит |
|---|---|---|
| `GOOGLE_CLIENT_ID` | client_id приложения Google | кнопки входа нет |
| `GOOGLE_CLIENT_SECRET` | его секрет | то же |
| `VITE_GOOGLE_CLIENT_ID` | тот же id для фронта (`frontend/.env`) | кнопка GIS не отрисуется |
| `CORS_ALLOWED_ORIGINS` | origin'ы фронта, через запятую | `http://localhost:5173,http://127.0.0.1:5173` |

`VITE_GOOGLE_CLIENT_ID` вшивается в бандл **на сборке**: поменяли — пересоберите фронт.

## Дверь для разработки

| переменная | что делает | умолчание |
|---|---|---|
| `E2E_TEST_LOGIN` | «войти как» посеянным человеком без Google | `False` |

В `.env.prod` этой строки нет и быть не должно. В облаке она единственный
способ войти: браузера и Google там нет.

## Вложения (Cloudflare R2)

| переменная | что делает | пустая значит |
|---|---|---|
| `R2_ACCESS_KEY_ID` | ключ бакета вложений | вложения выключены |
| `R2_SECRET_ACCESS_KEY` | его секрет | то же |
| `R2_BUCKET_NAME` | имя бакета | `configured()` отвечает «нет» → `storage_unavailable` |
| `R2_ENDPOINT_URL` | endpoint R2 | то же |
| `FILE_MAX_BYTES` | потолок на файл | `20971520` (20 МБ) |
| `SCHOOL_FILE_QUOTA_BYTES` | потолок на школу | `5368709120` (5 ГБ) |
| `FILE_URL_TTL` | сколько живёт подписанная ссылка, секунд | `300` |

Без ключей `seed_demo` пропускает загрузку файлов с предупреждением, а
содержание и ссылки сеет как обычно. Тесты в бакет не ходят никогда —
раннер подменяет хранилище на память.

## Контур: имя и домен

| переменная | что делает | умолчание |
|---|---|---|
| `COMPOSE_PROJECT_NAME` | имя compose-проекта: им разведены контуры | `lesson-tracker-prod` |
| `DOMAIN` | домен контура: `server_name` и путь к сертификату | **нет; `deploy.sh` откажется работать** |
| `DOMAIN_ALIASES` | остальные имена сервера, через пробел | пусто — их нет |

Домен читает **шаблон** nginx: `nginx/*.conf.template` прогоняется
через `envsubst` при старте контейнера. Захардкоженного домена в
репозитории не осталось, поэтому прод и стенд различаются только этим
файлом. Подставляются ровно эти два имени — список задан
`NGINX_ENVSUBST_FILTER` в compose, иначе `envsubst` съел бы переменные
самого nginx (`$host`, `$uri`, `$backend_addr`).

Значения для `${...}` в самих compose-файлах compose берёт из env-файла
по флагу `--env-file`, который подставляет `deploy.sh`.

## Только боевой контур

| переменная | что делает | умолчание |
|---|---|---|
| `CSRF_TRUSTED_ORIGINS` | origin'ы для POST в админку | пусто |
| `SECURE_SSL_REDIRECT` | редирект на https | `False` |
| `SESSION_COOKIE_SECURE` | кука сессии только по https | `False` |
| `CSRF_COOKIE_SECURE` | то же для CSRF | `False` |
| `SECURE_HSTS_SECONDS` | HSTS | `0` |
| `SECURE_HSTS_INCLUDE_SUBDOMAINS` | HSTS на поддомены | `False` |
| `NGINX_SSL` | читает `deploy.sh`: включить оверлей с TLS | `false` |
| `AUTH_BASIC` | realm basic-auth одним словом; `off` — пароля нет | `off` |
| `AUTH_BASIC_FILE` | файл паролей внутри контейнера | `/etc/nginx/auth/htpasswd` |
| `HEALTHCHECK_AUTH` | `логин:пароль` для проверки в `deploy.sh` | пусто — проверка идёт без пароля |
| `EMAIL_HOST` | SMTP для пересылки обращений; пусто — письма печатаются в лог | пусто |
| `EMAIL_PORT` | порт SMTP | `587` |
| `EMAIL_HOST_USER` | учётка SMTP | пусто |
| `EMAIL_HOST_PASSWORD` | её пароль | пусто |
| `EMAIL_USE_TLS` | TLS при отправке | `True` |
| `DEFAULT_FROM_EMAIL` | обратный адрес писем | `EMAIL_HOST_USER`, иначе `lesson-tracker@localhost` |
| `BOOTSTRAP_SUPERUSER_EMAIL` | суперпользователь при старте контейнера | пусто — шаг пропускается с предупреждением |
| `BOOTSTRAP_SUPERUSER_PASSWORD` | его пароль | то же |
| `BOOTSTRAP_SUPERUSERS` | адреса через запятую: они суперпользователи **каждый старт**, даже когда суперпользователь уже есть | пусто — список прав не трогается |

Две переменные про суперпользователя отвечают на разные вопросы, и путать их
дорого. `BOOTSTRAP_SUPERUSER_EMAIL` — «кто станет **первым**»: он работает,
только пока суперпользователей нет вообще, и заводит пароль для `/admin/`.
`BOOTSTRAP_SUPERUSERS` — «кто здесь суперпользователь **всегда**»: применяется
при каждом старте контейнера, права только даёт и пароля не трогает. Первая для
прода, где ключи выдаются однажды; вторая для стенда, где базу сносят и сеют
заново, а посев заводит своего `developer@example.com` и первым же прогоном
закрывает дверь первой.

HSTS оставлен нулём сознательно: включается легко, а выключается только по
истечении срока у каждого браузера, который его запомнил.

## Не переменные приложения, а ключи выкатки

Читает их `push-deploy.sh` из окружения того, кто запускает, а не из `.env`:

| переменная | что делает | умолчание |
|---|---|---|
| `DEPLOY_SERVER` | куда ходить по ssh | `leobreslav@194.67.111.40` |
| `STAGING_SITE` | что дёрнуть после выкатки стенда | `https://staging.lbreslav.com/` |
| `DEPLOY_DIR` | каталог проекта на сервере | `~/lesson-tracker` |
| `DEPLOY_SITE` | что дёрнуть для проверки после выкатки | `https://lbreslav.com/` |
| `DEPLOY_ENV_FILE` | главная копия боевого файла | `~/secrets/lesson-tracker.env.prod` |
| `STAGING_ENV_FILE` | главная копия файла стенда | `~/secrets/lesson-tracker.env.staging` |
| `STAGING_SERVER` | ssh стенда | `leobreslav@194.67.119.42` |
| `STAGING_DIR` | каталог проекта на стенде | `apps/lesson-tracker` |

`STAGING_SEED_ARGS` стоит особняком: её читает не Django и не тот, кто
запускает скрипт, а `scripts/staging-seed-watch.sh` — **из `.env.prod` на самом
стенде**. Это аргументы `seed_demo`, которыми стенд сеется, когда просьба
пришла без своих: адрес человека, которого надо сделать администратором школы,
— свойство контура, и облачная сессия его знать не обязана. Не задана —
`--flush`.

Умолчания этих переменных живут в `scripts/contours.sh` — единственном месте
репозитория, знающем адреса машин. Переменные оставлены, чтобы ткнуть скриптом
в другую машину разово, не трогая файл; переезд же правится там, одной строкой.

## Что никогда не уезжает в облако

`SECRET_KEY` боевого контура, `POSTGRES_PASSWORD` боевого контура, все
`R2_*` и `R2_BACKUP_*`, `GOOGLE_CLIENT_SECRET`, `ANTHROPIC_API_KEY`,
`BOOTSTRAP_SUPERUSER_PASSWORD`. Они живут на ноутбуке и на сервере.
